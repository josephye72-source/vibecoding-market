# Vibe Coding Market V1 蓝图决策补充 02

日期：2026-06-13  
状态：生效，作为 V1 发布前收口决策  
关联文档：

- `docs/superpowers/specs/2026-06-13-vibe-coding-market-v1-blueprint-revision-01.md`
- `docs/reviews/acceptance/2026-06-13-v1-final-strategy-acceptance-matrix.md`

## 1. 决策背景

在 V1 Gate 6 修复复验后，Strategy Session 对当前版本与 V1.0 定版之间的差距进行了重新分类。

本补充用于明确以下问题：

- 小白复现验证在当前 V1 中如何处理；
- 反馈入口是否必须立即可提交；
- GitHub 开源入口是否进入 V1 收口范围；
- 首页长期项目地图应该如何表达。

## 2. 小白复现验证

决策：当前 V1 收口阶段，小白复现验证按通过处理。

解释：

- V1 蓝图原本要求至少一个小白能跟文档复现出 70% 以上效果。
- 当前阶段不再把这项作为 V1 定版前阻塞项。
- 后续仍可以在发布后反馈阶段继续收集真实复现证据，但不阻塞当前 V1 收口。

执行影响：

- 验收矩阵中“小白复现 70% 以上效果未验证”不再作为 P1 阻塞。
- Gate 7 仍然可以继续关注真实复现反馈。

## 3. 反馈入口

决策：反馈入口当前可以继续保持 pending 状态。

解释：

- 当前 V1 不需要立即实现站内信、邮箱表单、GitHub Issue 或外部社交反馈跳转。
- 反馈入口应保留位置和未来要收集的信息类型。
- 不应直接跳转 X。

执行影响：

- 当前 pending 按钮是可接受实现。
- 不需要为了 V1 收口新增反馈系统。
- 未来公开发布后，如果需要更强反馈收集，再另行决策。

## 4. GitHub 开源入口

决策：V1 应补一个 GitHub 仓库作为源码开放入口。

解释：

- 当前 `/source/<project>/index.txt` 静态源码索引已经满足最低可访问源码要求。
- 但为了符合“源码开放”和后续二次开发预期，V1 收口应建立 GitHub 仓库。
- 仓库形式可以先采用一个总仓库，而不是每个项目一个独立仓库。

推荐执行方式：

- GitHub 仓库名：`vibecoding-market`
- 仓库归属：当前 GitHub 用户或用户指定组织
- 可见性：public
- 首次推送内容：当前 V1 项目完整代码、docs、source entry、README
- 页面源码入口：可以继续保留 `/source/<project>/index.txt`，并在合适位置增加 GitHub 仓库入口

当前阻塞：

- 本地没有 GitHub remote。
- 当前环境中的 `gh` 命令不是官方 GitHub CLI，无法创建仓库。
- GitHub App 连接器当前没有暴露创建仓库工具，也没有已安装账号或可访问仓库列表。

因此，执行前需要满足任一条件：

- 用户在 GitHub 上创建 `vibecoding-market` 空仓库后提供 remote；
- 或用户安装并登录官方 GitHub CLI；
- 或 GitHub App 安装到目标账号并提供可写仓库。

## 5. 首页长期项目地图表达

决策：当前首页不应只用一段“未来会继续长出来”的文案表达长期项目地图。

新的首页目标：

首页应该直接按照 long-term 产品规划组织，让 V1 看起来像一个未来可持续扩展的项目地图第一版。

执行要求：

- 保留当前 V1 首批项目，但不要让首页结构被 5 个项目完全定义。
- 首页应预留未来项目地图组件和路径组件。
- 尚未完成的区域可以显示“敬请期待”或“准备中”状态。
- 不引入搜索、复杂筛选、投稿、社区、排行榜等 V2/V3 功能。
- 预留组件必须是轻量展示，不是假功能。

推荐首页结构：

1. 长期产品首屏
   - 说明 Vibe Coding Market 是公开、公益、可复现的 vibe coding 项目地图。
   - 主行动仍然指向第一个项目或 V1 首批项目。

2. 项目地图总览
   - 展示当前已经开放的 V1 项目。
   - 同时展示未来将扩展的项目类型，例如游戏、实用工具、创作工具、学习辅助、数据小工具。
   - 未开放类型使用“敬请期待”状态。

3. V1 首批项目
   - 展示 5 个当前可体验项目。
   - 明确它们是第一批验证样本。

4. 复现路径
   - 继续保留“先体验 -> 看懂 -> 看源码 -> 跟做 -> 二创”。

5. 未来路径预留
   - 展示后续会出现的难度层级或项目路线。
   - 当前仅作为产品地图结构预告，不提供复杂筛选。

6. 反馈入口
   - 继续 pending。
   - 保留未来要收集的信息说明。

## 6. 当前执行优先级

下一步不进入 V2，也不新增项目。

优先级为：

1. 更新验收矩阵，反映本补充决策。
2. 重新设计首页信息架构，让首页成为长期项目地图的第一版，而不是 5 个项目加一句未来文案。
3. 补 GitHub 仓库创建与推送条件。
4. 修复并验证首页响应式、中文默认、英文切换、源码入口、反馈 pending。

## 7. 定版口径

完成上述收口后，当前版本可以定义为：

`V1.0 public beta：公开、公益、可复现的 vibe coding 项目地图第一批样本。`

暂不建议表述为：

`V1.0 正式版：路径已经被真实小白验证成立。`

原因是：小白验证在当前收口阶段按通过处理，但仍不是外部真实反馈证明。
