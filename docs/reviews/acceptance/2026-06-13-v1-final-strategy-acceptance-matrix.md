# V1.0 发布前策略验收矩阵

日期：2026-06-13  
对象：Vibe Coding Market V1.0 当前实现  
用途：判断当前版本距离 V1.0 定版还有多远，以及下一步应继续修、增功能，还是定版  
结论：当前版本达到 Gate 6 工程发布候选线；GitHub 开源仓库已建立，V1 收口剩余重点转为首页长期项目地图重构和站点内 GitHub 入口接入

## 1. 本矩阵的判断口径

本矩阵同时对照以下基线：

- `docs/superpowers/specs/2026-06-13-vibe-coding-market-v1-blueprint-revision-01.md`
- `docs/superpowers/specs/2026-06-13-vibe-coding-market-v1-blueprint-decision-addendum-02.md`
- `docs/superpowers/specs/2026-06-13-vibe-coding-market-strategy-session-charter.md`
- `docs/reviews/acceptance/2026-06-13-v1-gate6-release-independent-rereview-acceptance-report.md`

状态定义：

- 通过：当前版本已经满足 V1.0 基线。
- 部分通过：方向正确，但还存在产品表达、执行质量或外部依赖缺口。
- 未验证：代码或文档可能存在，但还没有真实证据证明路径成立。
- 未通过：当前实现与 V1.0 基线冲突。

阻塞定义：

- P0：必须先解决，否则不能继续验收。
- P1：阻塞 V1.0 public beta 收口。
- P2：不阻塞 public beta，但建议发布前修复。
- Decision：不是代码问题，需要产品层决策。
- External：需要外部授权、外部账号、GitHub 仓库或人工操作。
- Evidence：不是实现问题，需要真实验证证据。

归因定义：

- 蓝图变更：差距没有被 V1 蓝图定义，或蓝图定义之间存在冲突，需要先修订蓝图。
- 代码/内容修复：蓝图已经定义，当前实现没有做到或做得不好，应回到 V1 代码或内容执行。
- 轻量功能补齐：蓝图已经定义了目标，但当前缺少一个极轻实现来闭环，不应扩展成 V2/V3 能力。
- 外部条件补齐：实现方向明确，但需要 GitHub 仓库、remote、授权或外部创建动作。
- 验证证据补齐：蓝图已经定义成功标准，但当前缺真实用户或真实路径证据。
- 暂不处理：新决策已经允许当前状态，不进入本轮 V1 收口。

## 2. 总体判断

当前版本可以称为 `V1.0 Release Candidate`。

根据蓝图决策补充 02，小白复现验证当前按通过处理，反馈入口可以继续 pending。GitHub 仓库已于 2026-06-13 创建并推送：

- 仓库：`https://github.com/josephye72-source/vibecoding-market`
- 可见性：Public
- 当前远端：`origin`
- 当前默认分支：`v1-implementation`

因此，当前最主要的剩余差距变为：

- 首页长期项目地图结构仍然太弱；
- `.map-intent` 视觉容器错位；
- 站点内还没有接入 GitHub 仓库入口，这属于 V1 执行团队的代码/内容修复项。

当前不建议进入 V2，不建议增加新项目，不建议新增搜索、筛选、投稿、社区或反馈系统。

更合适的下一步是：做一次非常短的 `V1.0 Finalization`，由执行团队把首页改成长期项目地图第一版，并把已建立的 GitHub 仓库入口接入站点。

## 4. 当前版本与 V1.0 的真实差距

### 已经基本完成的部分

- 核心站点结构。
- 5 个首批项目。
- 5 个在线 demo。
- 5 个项目详情页。
- 5 套中文优先项目文档。
- 静态源码入口。
- 中文默认体验。
- 英文切换能力。
- 无后端、无数据库、无登录、无 API。
- Gate 6 上次 P1 阻塞项修复。
- 小白复现验证按产品决策通过处理。
- 反馈入口继续 pending，且不跳 X。
- GitHub public 仓库与远端推送。

### 还差的部分

#### 差距 1：首页长期项目地图表达仍然太弱

归因：代码/内容修复。  
蓝图状态：蓝图决策补充 02 已明确，首页应直接按照 long-term 产品规划组织，预留未来项目地图组件和路径组件。  
当前问题：现在只是 5 个项目、复现路径，再加一段“项目地图会继续长出来”的文案。这个表达太轻，也不符合用户希望的 long-term 首页结构。

建议：

- 将首页改成长期项目地图第一版。
- 保留当前 V1 首批项目。
- 增加未来项目类型/路径的轻量占位组件。
- 未开放区域使用“敬请期待”或“准备中”状态。
- 不引入搜索、复杂筛选、投稿、社区、排行榜。

#### 差距 2：站点内 GitHub 仓库入口尚未接入

归因：代码/内容修复。

蓝图状态：蓝图决策补充 02 已明确，V1 应补一个 GitHub 仓库作为源码开放入口。

当前状态：GitHub public 仓库已经建立，本地 `origin` 已配置，当前分支 `v1-implementation` 已推送。

当前问题：站点首页或源码相关区域尚未把公开仓库作为入口展示给用户。

建议：

- 保留 `/source/<project>/index.txt` 作为每个项目的站内源码索引。
- 在首页或源码相关区域增加 GitHub 仓库入口。
- 这项由 V1 执行团队处理，不由 Strategy Session 直接改代码。

#### 差距 3：首页 `.map-intent` 模块容器错位

归因：代码/内容修复。  
蓝图状态：V1 蓝图已定义整站视觉应服务长期项目地图。  
当前问题：桌面和移动端截图里该模块没有跟随主内容容器。

建议：

- 如果首页整体重构，该模块应被替换为长期项目地图结构。
- 如果不重构，也至少要把 `.map-intent` 纳入统一页面容器。

#### 差距 4：英文学习文档策略未定

归因：蓝图变更。  
蓝图状态：V1 蓝图要求明确英文文档策略。  
当前处理：本轮 V1 收口不把英文学习文档作为阻塞项；当前只要求 UI 英文切换成立。

建议：

- 蓝图后续补一句：V1 只保证英文 UI 主路径，英文学习文档进入后续版本或由本地化内容生成策略另行决定。

## 7. 是否应该继续修、增功能，还是定版

### 不建议现在增功能

原因：

- 当前缺口不是功能数量不足。
- 增加项目、筛选、搜索、站内反馈、社区、投稿都会把 V1 拉向 V2/V3。
- 现在最该修的是首页长期产品表达和站点内 GitHub 入口。

### 建议继续做一次短修复

短修复范围应该聚焦：

1. 重构首页为长期项目地图第一版。
2. 接入已建立的 GitHub 开源仓库入口。
3. 保持反馈 pending，不新增反馈系统。

这三件事完成后，再定版会稳很多。

### 什么时候可以定版

如果目标是内部版本冻结：

- 首页长期地图重构完成后，可以定为 `V1.0 RC`。

如果目标是公开发社媒收反馈：

- 可以保持反馈 pending。
- 建议先补站点内 GitHub 仓库入口。
- 然后可以定为 `V1.0 public beta`。

如果目标是正式宣布 V1.0 路径成立：

- 当前小白验证按通过处理。
- 但公开表达上仍建议保守，不宣称已被真实外部小白验证。

## 8. 下一步建议

范围只包含：
