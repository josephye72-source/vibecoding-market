## 总体验收结论

V1 当前可以视为一个技术上较稳定的 release candidate，但不能作为正式 V1.0 公开发布。

阻塞原因主要有三类：

1. 语言与本地化不符合要求：当前没有中英文切换机制，默认体验也不是完整中文。
2. 首页首屏定位有偏差：它把整个 Vibe Coding Market 描述成 “5 个纯 Web 小项目”，这只是 V1 范围，不应该成为长期产品身份。
3. 整站信息架构过度依赖当前 5 个项目，没有呈现长期项目地图、路径和复现系统的页面骨架。
4. 源码开放入口不足：当前“查看源代码”只是跳到站内源码导览锚点，不是真正的 GitHub 仓库、源码树或可下载源码入口。
5. 反馈入口策略未定：当前按钮直接跳到 X 发帖，但现阶段不应该过早绑定外部社交平台。

这些问题不是单个文案或 UI 细节，而是会影响站点是否符合我们的大蓝图、北极星和 V1 发布目标。

## 阻塞问题

### P1 - 首页 Hero 把长期产品收窄成 V1 范围

首页第一屏目前把 Vibe Coding Market 描述成一组“5 个纯 Web 小项目”。这对 V1 是准确的，但不适合作为整个长期产品的定义。

证据：

- `src/components/HomePage.ts` 的 hero lede 是：`5 个纯 Web 小项目，带你用 Codex 从 0 做到可发布`。
- hero 副文案描述的是一条单一路径，适合作为 V1 首批项目说明，但不足以承载整个产品长期定位。
- 当前首屏会让用户以为这个站点就是一个固定的 5 项目 starter pack，而不是会持续扩展的公开项目地图。

验收影响：

这不符合大蓝图里的长期定位。首页第一屏应该表达“公开、公益、可复现的 vibe coding 项目地图 / 项目学习空间”；“5 个纯 Web 小项目”应该下沉为 V1 或首批项目说明。

### P1 - 整站布局过度依赖当前 5 个项目

当前页面结构主要围绕 V1 的 5 个项目展开：Hero、四步新手路径、5 张项目卡、反馈入口。这个结构能承载 V1 release candidate，但还不像一个长期的 Vibe Coding Market。

大蓝图里的长期产品形态至少包含四层：项目画廊、复现系统、项目路径、公开迭代。当前页面没有把这些层级作为长期站点骨架呈现出来，而是把当前 5 个项目当成了整个站点的主体和边界。

这不是单纯的实现问题。旧 V1 执行基线本身对首页 Hero 的表达也偏向“5 个项目路径验证包”，因此后续需要先按新版 V1 蓝图修订版修正产品表达，再做实现调整。

证据：

- `src/components/HomePage.ts` 只有 hero、path、projects、feedback 四个主要 section。
- 导航也绑定为首页、5 个项目、新手路径、反馈，没有更宏观的“项目地图”“路径”“复现方法”等结构。
- 页面没有把当前 5 个项目明确放进“V1 / 首批项目”语境中，也没有为未来 2.0 的路径化、3.0 的开放迭代保留正确的页面语义。

验收影响：

这不意味着 V1 要提前实现复杂筛选、社区、投稿或完整路径推荐；这些仍然不能做。但 V1 的整站布局应该先建立长期产品骨架：长期产品是什么、当前版本有什么、用户如何走复现路径、未来项目如何被组织。当前设计太依赖 5 个项目本身，因此不符合宏观期望。

### P1 - 源码入口不是真正的公开源码入口

项目承诺包含开源和可复现，但当前“查看源代码”并没有打开 GitHub 仓库、源码树、可下载源码包或具体代码文件，而是跳回站内详情页的源码导览区。

证据：

- `src/data/projects.ts` 中每个项目的 `links.source` 都是 `#/projects/{slug}?section=source-guide`。
- `src/components/ProjectDetail.ts` 把这个链接渲染成 `查看源代码`。
- source-guide 区块会说明本地应该看哪些文件，但没有提供真正的公开仓库入口。

验收影响：

这削弱了“体验 -> 看懂 -> 源码 -> 复现”的核心闭环。公开发布前，每个项目至少应有清晰的 GitHub 源码入口、源码目录入口，或一个明确可访问的公开源码包。

### P1 - 没有中英文切换机制

当前没有 locale / i18n 机制，用户无法在中文与英文之间切换。

证据：

- `index.html` 固定声明 `lang="zh-CN"`，但没有语言状态或备用语言入口。
- `src/main.ts` 只按 hash 路由渲染页面，没有 locale 参数或语言状态。
- `src/components/AppShell.ts` 导航只有首页、5 个项目、新手路径、反馈，没有语言切换入口。
- `src` 中没有发现统一的 locale dictionary、语言状态或语言切换逻辑。

验收影响：

这不满足新增 V1 语言要求：默认中文，并支持切换英文版。

### P1 - 反馈入口过早绑定 X 平台

当前首页反馈按钮直接打开 X 发帖 intent。这个实现太像“已经进入公开推广/外部传播阶段”的反馈机制，也过早绑定了一个具体平台。

证据：

- `src/components/HomePage.ts` 中 `feedbackHref` 是 `https://x.com/intent/post?...`。
- 首页反馈区文案是 `用公开话题告诉我们四件事...`。
- 反馈按钮文案是 `发布话题反馈`，点击后会离开站点并进入 X 发帖流程。

验收影响：

当前阶段可以保留反馈按钮的位置，但不应该直接启用 X 发帖功能。反馈方式仍需产品层决策：可以后续选择邮箱、站内信、GitHub Issue、轻量表单或社交话题，但不应在 V1 release candidate 中默认绑死到 X。

### P1 - 核心产品界面存在大面积中英文混杂

首页和项目卡使用中文结构，但项目名、summary、Level、minutes、skills 等大量内容仍是英文。

证据：

- `src/data/projects.ts` 中存在 `Focus Pomodoro`、`Memory Cards`、`Level 1`、`45 minutes`、`timer`、`state`、`shuffle`、`localStorage` 等用户可见英文。
- `src/components/ProjectDetail.ts` 中有英文详情文案，例如 `The ... demo is live` 和 `Open Live Demo`。
- `src/data/projectDocs.ts` 中的文档标签是 `Codex From Zero`、`Source Guide`、`Complexity Map`、`FAQ`、`Remix Prompts`。

验收影响：

这会直接影响中文小白用户理解路径，也破坏站点默认中文的产品承诺。

### P1 - 游戏 demo 的语言问题确实存在

Memory Cards demo 的实际 UI 基本是英文。

证据：

- `src/demos/memory/render.ts` 中反馈文案包括 `Flip two cards to find a pair.`、`Pick one more card.`、`Match found.` 等。
- demo 中显示 `Memory Cards`、`Moves`、`Restart game`，aria-label 也是英文。
- 渲染抽检时，实际页面显示了 `Moves`、`Pick one more card.`、`Restart game`。

验收影响：

这与用户现场指出的问题一致，属于发布阻塞。

### P1 - 其他 demo 也存在同类语言问题

语言问题并不只在游戏项目里。

证据：

- `src/demos/pomodoro/render.ts` 包含 `Focus`、`Break`、`Start`、`Pause`、`Reset`、`Status`、`Completed Today`。
- `src/demos/ledger/render.ts` 包含 `Type`、`Income`、`Expense`、`Amount`、`Category`、`Add record`。
- `src/demos/habits/render.ts` 包含 `Habit Grid`、`Habit calendar`。
- `src/demos/split/render.ts` 包含 `Total`、`Items`、`Participants`、`Each person`、`Copy summary`。

验收影响：

五个 demo 都必须纳入同一套语言系统，不能只修游戏页。

### P1 - 项目文档不是中文优先

项目文档存在，但很多不是面向中文小白的中文优先复现路径。

证据：

- `docs/projects/memory/codex-from-zero.md` 标题是 `Memory Cards: Codex From Zero`。
- `docs/projects/memory/source-guide.md` 标题是 `Memory Cards Source Guide`。
- `docs/projects/memory/faq.md` 使用英文问题标题。
- `docs/projects/memory/remix-prompts.md` 使用英文 remix 标题和 prompt。

验收影响：

V1 的价值依赖“小白可以跟文档复现”。如果默认文档是英文优先，这条路径就没有真正成立。

## 复验前必须完成的修复

1. 重新定义首页 Hero。
   - Hero 应表达 Vibe Coding Market 的长期身份：公开、公益、可复现的 vibe coding 项目地图。
   - 第一屏不应把整个站点定义成 `5 个项目`。
   - `5 个纯 Web 小项目` 应作为 V1 / 首批项目范围出现。
   - 首页仍然要保留小白友好的路径表达：体验、看懂、复现、二创。

2. 调整整站信息架构与页面布局。
   - 页面应先承载长期产品骨架，而不是只承载当前 5 个项目。
   - 建议至少区分：长期定位、当前 V1 首批项目、复现路径 / 方法、项目路径预告或项目地图语义、反馈入口。
   - 当前 5 个项目应作为“首批项目 / V1 release”模块，而不是整个站点的全部定义。
   - 不要因此提前引入复杂筛选、账号、社区、投稿、排行或完整 V2 路径系统。

3. 接入真实源码入口。
   - 每个项目应有公开 GitHub 源码入口、源码树链接，或清晰可下载的源码包。
   - `查看源代码` 不应只跳到 source-guide 锚点。
   - source-guide 可以保留，但它应该补充源码入口，而不是替代源码入口。

4. 重新确定反馈入口策略。
   - 首页可以保留反馈按钮位置，但当前不应直接跳转 X。
   - 如果反馈渠道暂未确定，按钮可以表现为“反馈方式准备中”或进入一个站内说明区。
   - 后续可选方案包括邮箱、站内信、GitHub Issue、轻量表单或社交话题。
   - 选定反馈方式前，不应让用户误以为 X 是唯一或正式反馈渠道。

5. 建立语言模型。
   - 默认语言：中文。
   - 第二语言：英文。
   - App shell 中增加清晰的语言切换入口。
   - 用户选择的语言应保存在本地浏览器状态中。

6. 抽离用户可见文案。
   - App shell；
   - 首页；
   - 项目卡；
   - 项目详情页模板；
   - 项目元数据；
   - 文档标签；
   - 五个 demo；
   - 动态状态、校验、空状态、错误提示。

7. 完成默认中文体验。
   - 项目可以保留品牌型英文名，但需要配套中文展示名。
   - `Codex`、`GitHub`、文件路径、API 名称等专有名词可以保留英文。
   - 用户可见标签、说明、状态、按钮、文档应默认中文。

8. 完成英文模式。
   - 切换英文后，导航、首页、项目卡、详情页、demo、文档标签都应更新。
   - 需要明确英文文档是独立文件，还是由本地化内容渲染。

9. 增加语言验收测试。
   - E2E：默认打开页面是中文。
   - E2E：语言切换能改变 App shell、至少一张项目卡、一个详情页和一个 demo。
   - 单元或数据测试：每个项目都有必要的 `zh` 和 `en` 用户可见字段。

## 复验通过标准

V1 只有在以下条件同时满足时，才能重新进入 Gate 6 发布验收：

- 首页第一屏表达长期产品身份，而不是把整个站点定义为 5 个项目。
- `5 个项目` 被明确表达为 V1 / 当前首批项目范围。
- 整站布局体现长期产品骨架，当前 5 个项目只是首批项目模块，而不是整个站点边界。
- 页面为未来项目地图、路径和复现系统保留清晰语义，但不提前实现 V2/V3 复杂功能。
- 每个项目都有真实公开源码入口，而不是只有 source-guide 锚点。
- 反馈入口不再直接绑定 X；如果渠道未定，应表现为占位或站内说明。
- 默认首页、项目卡、详情页、demo 是中文优先。
- 英文版可以通过清晰入口切换。
- Memory Cards demo 在中文模式下不再显示英文 UI。
- 五个 demo 的动态状态文案都已本地化。
- 项目文档入口和至少中文复现文档是中文优先。
- 测试、构建、E2E 仍然全绿。
- 修复过程中没有引入后端、数据库、登录、支付、API、社区、排行、投稿等 V1 非目标。

## 最终判定

本轮 V1 发布验收不通过。

当前实现应继续作为 release candidate 迭代，先完成长期定位、整站信息架构、源码入口、反馈入口、语言与文档修复。修复完成后，再按同样命名规范发起一次 Gate 6 复验。
